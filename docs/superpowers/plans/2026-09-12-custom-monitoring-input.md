# 自定义监测输入断链修复

对应 personal_task_progress.md 阶段 6 前端输入与阶段 7 端到端联调的缺陷修复；仅修改 agent1/，不调整阶段范围。

目标：自定义文字参与确定性风险评分和资源核算，原始文字及解析指标进入状态、证据和前端结果；场景卡片继续使用其显式 fixture。

方案：自定义提交使用 scenario_id=custom。入口解析带单位的中文监测摘要为独立数据契约，校验失败返回 422，不回退黄色场景。摘要直接映射规则特征，不伪造逐条微震事件或坐标。缺失高能事件数/空间比例时标注评分依据不完整。资源按用户明确提供的可用/需求核算，缺数据为 unknown；缺处置后观测时反思为 unknown。沿用 simulation-v1 评分阈值，阈值性质在证据中说明。

执行与验收：

- [x] tests/test_custom_monitoring.py：10项回归覆盖解析低/高风险、中文单位、缺失与错误值、资源不足/缺失、摘要不生成虚假事件、实际状态机和审批。
- [x] services/monitoring_task.py：解析与数据校验；perception_warning_service.py 复用特征评分入口。
- [x] workflow_state.py / workflow_runner.py / workflow_nodes.py：自定义数据贯穿节点和检查点，保留预设场景行为；自定义反思不编造风险下降。
- [x] api/server.py：自定义请求校验和错误提示；前端自定义提交改为 custom，启动失败恢复输入状态并保留待修正文本。
- [x] 自定义回归10/10、原有7场景/6路径、数据契约5/5和前端构建通过。浏览器实际提交：normal 0.075、yellow 0.4075、red等待人工审批、缺字段422且输入可修正。红色验证没有代替用户批准动作。

验证范围：已支持的中文指标格式与结构化 JSON，非任意开放文本问答。未知指标不暗中套用 fixture。完整原始监测序列接口不在本次摘要断链修复范围内。
