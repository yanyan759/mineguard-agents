# 可复现公开源码包设计

## 目标

公开仓库默认只下载源码、部署配置、脱敏 fixture、模板和资料索引；不默认下载大型研究语料、原始事故报告或可能包含隐私的数据。全新用户完成依赖安装后，不配置可选语料也能启动前端、运行六 Agent 演示并获得结构化结果。

## 方案

仓库分为三个数据层：

1. `tests/fixtures/` 保留小型、脱敏、可测试的演示数据。这些文件属于软件验收输入，保证基础工作流可复现。
2. `煤矿资料收集/` 和 `deploy/ragflow/docs/real/` 只保留索引、模板、来源登记和导入说明。真实 PDF、HTML、原始报告和完整论文作为可选资料，由用户按授权自行下载或从 Release 获取。
3. `真实数据投喂/` 只保留结构化模板、字段示例和离线整理脚本，不放入真实矿井数据或未确认授权的原始资料。

知识检索默认使用 `tests/fixtures` 中的脱敏 YAML；可选真实资料存在时才建立资料索引或交给 RAGFlow。缺少可选资料不应阻断基础启动，结果中明确记录当前使用的 fixture 或“可选资料未配置”。

## 运行与验收

README 必须同时说明：

- 全新环境如何启动 Redis、后端和前端；
- 如何点击场景或提交示例输入并验证六 Agent 结果；
- 可选资料的来源、授权、下载、哈希和导入方式；
- 不应把 `.env`、用户附件、运行账本、原始矿井数据提交到公共仓库。

发布前检查仓库跟踪文件的体积、敏感字段、重复语料和历史提交；移除大型语料后，基础 fixture、API、工作流和前端构建必须通过测试。
