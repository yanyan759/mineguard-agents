# 页面与六Agent接入验收记录

本次仅修改agent1/，沿用已确认的补齐方案。页面提交已接到原`POST /api/workflow/start`，由同一个LangGraph执行感知预警、知识检索、调度决策、资源评估、协同管控、反思迭代。知识写回是辅助节点，不冒充第七Agent。正常摘要仍按实际条件只执行感知；原始数据未定级会进入六节点核验流程。

## 实现与输入方式

1. 展开页面“原始监测记录”，可上传带元数据的JSON，或CSV加JSON元数据；也可载入两份NIOSH真实历史样本。点击“校验并送入六 Agent”启动当前会话工作流。文件只是上传不会自动参与计算；实际提交前核对会话归属、原始记录及SHA256。
2. 输入可缺b值、设备在线/缺失率、坐标，未知保持null。统计计算事件数、最大/总能量、频次；可选能量MLE方法声明最小能量和样本量，样本不足不输出b值。拒绝重复事件ID、隐式时区、窗口外事件、非法单位、非有限数和溢出。
3. 参数文件在`config/assessment_profiles/`按严格Schema读取，并在运行开始冻结。当前可执行方法为statistics-v1及Elk Creek双指标研究方法；核验矿井、来源、区域、窗口及适用期间，不匹配时保留指标并报告不适用。更改研究参数不等于获得现场批准，研究报警不映射成五色现场等级或事故概率。
4. 自定义摘要入口兼容保留，原0.195评分仍明确属于simulation-v1演示评分。已修正“无能量时间基线却称升高”“只比较首末b值却称持续下降”等措辞。
5. 完成原始数据任务后，展开“补交执行反馈与新观测”，填写报告人、后续任务JSON及可选动作报告。形成不可覆盖的父子运行；同请求幂等，时序/测区/动作校验在后端执行。复核启动请求失败时保留已保存反馈和输入，可重试。
6. 节点开始事件和耗时来自实际调用。完成状态不能被较早发出的运行中查询覆盖；断线重连按原运行编号查询，不重启任务。新结果及审批自动定位，原始编辑区提交后折叠；对话、轨迹、结果、审批正文分别可滚动。
7. 业务HTTP适配与页面状态、可信研判身份、显式库存读取、通知、回执见`business-http-contract.md`。当前真实业务服务未配置，未发送现场通知或生产指令。

## 实际边界

计算代码可用、方法适用、矿井现场有效分别记录。本次解决的是页面与工作流、记录计算、反馈复核和既定HTTP契约的接入，不能把NIOSH研究阈值当作任意矿井的批准参数。Elk Creek回放曾得到约41.64%报警窗口、0.83%窗口precision，仍不足以支持现场采用。

没有设备在线证据、现场标定/批准方案、矿方身份/库存/通知/回执协议与凭据时，系统会明确给出缺项。当前没有可自动下发的现场批准生产方案，生产工单仍被阻断。实际外部字段映射和现场验收需收到这些资料后完成；未以“代码已经运行”冒充现场可用。

终态、反馈与业务请求已本机持久化；正在运行/待审批任务能否跨进程恢复取决于原检查点配置。本次已验证终态跨重启查询，未宣称所有中途任务都能自动恢复。
