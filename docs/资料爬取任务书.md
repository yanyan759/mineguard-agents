# 公开资料来源与导入说明

本文件说明 MineGuard Agents 可以使用哪些公开资料、如何记录来源以及如何将资料导入配置。文件名保留是为了兼容已有链接；内容不要求用户执行网页抓取，也不把公开资料视为某一矿井的现场标定结果。

## 1. 先确定资料用途

不同资料进入系统的路径不同：

| 用途 | 资料示例 | 导入后的节点 |
| --- | --- | --- |
| 历史案例检索 | 官方事故调查报告、事故通报、公开复盘 | 知识检索、调度决策 |
| 条款与制度检索 | 现行法规、行业标准、企业制度、应急预案 | 知识检索、审批约束 |
| 方案与资源核算 | 经批准的支护方案、设备清单、材料台账 | 调度决策、资源评估 |
| 方法和参数参考 | 公开论文、技术报告、标准附录 | 参数配置和方法说明 |
| 抽取模型训练 | 经授权且已脱敏的文本标注 | 离线 UIE 训练或评估 |

公开资料可以补充知识检索和方法依据，但不能替代矿方确认的阈值、岗位权限、实时库存或现场方案。

## 2. 建议的公开来源类型

优先选择可核验的一手来源：

1. 国家和省级政府部门、矿山安全监察机构发布的法规、标准、事故调查报告和行政公告。
2. 标准发布机构或正式出版物提供的现行标准文本和版本信息。
3. 论文作者、期刊官网、科研机构仓储公开的研究论文和数据说明。
4. 企业公开披露的技术报告、采购公告和应急预案。涉及内部安全资料时，必须确认分发权限。
5. 项目使用者依法取得并获授权的矿井资料，例如历史监测摘要、支护方案和库存快照。

检索时记录发布机构、标题、版本、发布日期、原始地址和访问日期。网页内容可能更新或下线，建议同时保存授权的 PDF/HTML 原件及 SHA-256 哈希。

## 3. 来源登记模板

以下是本地来源登记表的建议格式，用于随资料保存，不是前端上传 API 的字段契约。前端实际元数据使用 `category`、`title`、`source`、`version`、`observed_at` 和测区标识，见 [资料准备与导入规范](真实资料爬取与整理要求清单.md)。

```yaml
source_name: 煤矿安全规程
source_type: regulation
publisher: 发布机构
version: 现行版本或修订号
published_at: "2025-01-01"
collected_at: "2026-09-19T10:00:00+08:00"
source_url: https://example.org/source
local_file: 01_煤矿安全规程.pdf
scope: 适用范围
license_or_permission: 公开访问或授权编号
notes: OCR、人工复核和已知限制
```

`source_url` 不可访问时，保留原始发布机构和本地文件授权说明。不要把搜索结果页、个人网盘或无法核验的二次转载作为唯一来源。

## 4. 资料准备建议

### 4.1 事故案例

优先使用完整调查报告。整理时保留事故发生时间、地点、原因、前兆、处置、后果、整改要求和原文来源。没有量化监测数据时写明“原文未提供”，不要根据报道标题推算能量、频次或风险等级。

### 4.2 法规、标准和制度

保留全文、版本和条款编号。需要条款检索时，使用可提取文本的 PDF/DOCX/TXT，并人工检查 OCR。企业制度只能代表发布企业的职责安排，不能直接推导另一矿井的权限。

### 4.3 论文和技术报告

记录研究对象、样本范围、统计窗口、单位、方法和局限。论文中的参数是研究结论或案例条件，不应直接作为生产阈值。配置页面中的规则必须另行注明矿方批准依据。

### 4.4 资源和业务资料

实时库存、人员资质、设备状态、通知通道和工单回执通常来自矿方系统，公开网页不能替代。通过业务 HTTP 契约接入时，需要部署者提供接口地址、认证方式、字段映射和测试对象。

## 5. 导入前检查

- 文件来源、授权状态、版本和采集日期已登记。
- PDF/DOCX 可以提取正文，扫描件已 OCR 并人工校对。
- 事故案例、方案和台账符合 [`资料准备与导入规范`](真实资料爬取与整理要求清单.md) 的字段要求。
- 资料中的矿井、测区、巷道、设备和岗位名称与本次配置一致。
- 量化值带单位、统计窗口和原文出处；缺失值保持缺失。
- 文件中已删除个人凭据、接口密钥和不应公开的人员信息。

## 6. 在项目中使用

1. 展开前端“矿方资料与参数配置”，选择类别并上传支持格式的文件。知识 JSON 使用 `text` / `terms`，台账使用资源 JSON/CSV；先整理文件再上传。
2. 查看解析状态，确认文件已校验、已入库。
3. 保存包含矿井、测区、有效期、版本和资料选择的配置。
4. 启动自定义实际数据任务，检查结果中的 `evidence` 和 `provenance`。
5. 若更换资料或参数，保存新版本后重新运行；历史运行保留原快照。

系统不会因为一个文件存在就宣称知识已验证，也不会把未配置的外部服务显示为已连接。资料引用和库存证据会显示在运行归档中。

## 7. 分发与版权

公开仓库只应包含可合法分发的资料、脱敏示例和来源说明。大体积原件或有分发限制的资料可以不提交到 Git，改为提供来源、下载方法和导入模板。用户在自己的环境中导入资料时，应遵守资料发布方的版权、隐私和数据安全要求。
