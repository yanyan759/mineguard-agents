# 事故案例资料

本目录存放可用于 MineGuard Agents 知识检索和案例回放的结构化事故资料。示例案例来自公开报告，并保留来源映射；导入矿井自己的资料前，请确认已获得使用和分发授权。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `事故案例_真实报告FINAL.yaml` | 已整理的案例集合，包含来源元数据 |
| `事故案例_真实报告V1.yaml` | 早期整理版本，便于复现整理过程 |
| `codex_URL映射.json` | 案例编号与公开来源的对应关系 |
| `_生成fixtures.py`、`_整合脚本*.py` | 本地格式转换和合并工具 |
| `非报告项说明.md` | 说明未纳入案例集合的资料及原因 |

## 离线案例字段

以下为 YAML 归档字段的占位示例，实际集合位于顶层 `cases` 列表中；这不是前端上传格式：

```yaml
case_id: real-2024-001
location: 某矿某采区某工作面
occurred_at: "2024-10-23T04:20:00+08:00"
risk_level: orange
causes: ["原报告中的原因"]
precursors: ["原报告中的前兆"]
actions: ["预警触发后的处置"]
outcome: 原报告中的后果
lessons: ["整改要求"]
source: 发布机构及报告名称
```

量化值必须带原文依据和单位；报告没有提供的内容保持缺失并在备注中说明，不使用推算值补齐。`risk_level` 的映射依据应写入来源说明。

## 导入项目

前端不接受本目录 YAML 原样上传。在配置框下载“知识资料模板”，把所需案例的报告名称、来源、页码和核对摘要写入 `text`，检索词写入 `terms`，保存为 JSON；也可上传对应的文字版报告。选择“历史案例”类别上传，勾选资料并保存配置后再启动任务。详见 [资料准备与导入规范](../../docs/真实资料爬取与整理要求清单.md)。

## 开发者整理工具

`_整合脚本*.py` 依赖相应版本及外部来源文件，运行前按脚本检查输入并保留副本。`_生成fixtures.py` 会将 FINAL 转为测试资料中的真实案例库，属于开发者维护操作，不是前端导入步骤。`tests/validate_fixtures.py` 检查测试目录中的数据，不能视为对本目录任意新增案例的验证。

FINAL 中保留了 2017 年案例，因此集合不限定为近五年。`risk_level` 是整理标签，不能将事故等级直接换算为本次现场预警。部分动作是依据报告整理的建议，引用时应区别原文与整理内容。保留这些说明有助于评审者核对资料依据。
