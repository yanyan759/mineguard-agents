# 事故案例资料

本目录只提供事故案例字段说明和来源登记格式。公开仓库不保存真实事故报告、案例集合或来源映射；用户应在受控环境整理已获授权、已脱敏的资料。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `非报告项说明.md` | 说明未纳入案例集合的资料及原因 |

## 离线案例字段

以下为 YAML 归档字段的占位示例，实际集合位于顶层 `cases` 列表中；这不是前端上传格式：

```yaml
case_id: real-2024-001
location: 某矿某采区某工作面
occurred_at: "2024-10-23T04:20:00+08:00"
risk_level: orange
causes: ["原报告中的原因"]
precursors: ["原报告中的前兆"]
actions: ["预警触发后的处置"]
outcome: 原报告中的后果
lessons: ["整改要求"]
source: 发布机构及报告名称
```

量化值必须带原文依据和单位；报告没有提供的内容保持缺失并在备注中说明，不使用推算值补齐。`risk_level` 的映射依据应写入来源说明。

## 导入项目

前端不接受本目录 YAML 原样上传。在配置框下载“知识资料模板”，把所需案例的报告名称、来源、页码和核对摘要写入 `text`，检索词写入 `terms`，保存为 JSON；也可上传对应的文字版报告。选择“历史案例”类别上传，勾选资料并保存配置后再启动任务。详见 [资料准备与导入规范](../../docs/真实资料爬取与整理要求清单.md)。

## 与运行链路的关系

前端不接受本目录 YAML 原样上传。请在配置页面下载知识资料模板，把报告名称、来源、页码和核对摘要写入 `text`，检索词写入 `terms`，再选择“历史案例”类别上传。`tests/validate_fixtures.py` 检查的是脱敏测试 fixture，不能视为对用户新增案例的真实性验证。

案例年份由部署方按研究范围决定，不限定为近五年。`risk_level` 是整理标签，不能将事故等级直接换算为本次现场预警。部分动作是依据报告整理的建议，引用时应区别原文与整理内容。
