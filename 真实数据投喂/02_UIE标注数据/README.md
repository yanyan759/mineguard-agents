# 02_UIE标注数据 —— 投喂说明

## 你要做什么
1. 打开 `标注模板_空.csv`（UTF-8；Excel/WPS 打开如乱码，用记事本或 VS Code 打开，或告诉我转带 BOM 的版本）
2. 按 8 列表头填一行：`text`（原文 1-3 句）/ `entity`（主语，可空）/ `entity_type` / `relation`（可空）/ `object`（宾语，**必填**）/ `object_type`（**必填**）/ `confidence`（0-1）/ `source`（文档名）
3. 拿不准的列**留空**，别硬填
4. 每批存成 `标注_第N批_日期.csv` 放本目录
5. 成品长什么样 → 看 `标注示例_真实报告10条.csv` / `.jsonl`（逐字摘自真实事故报告）

## 速查
- 实体 7 类：地质构造 / 支护设备 / 顶板灾变 / 监测指标 / 处置规程 / 岗位角色 / 巷道分区
- 关系 7 类：诱发 / 支护 / 防控 / 监测 / 调度 / 上报 / 传导
- **详细操作手册**：`agent1/docs/真实资料爬取与整理要求清单.md` §2.5（6 段真实报告示范 + 覆盖度分配表 + 自查清单）
- 数量：保底 200、建议 300-500；可分批投喂，先 30-50 条验证格式
- 语料：`煤矿资料收集/05_近五年煤矿顶板事故通报/` 18+ 份报告 + `deploy/ragflow/docs/real` 160 份（PDF/HTML 由我转好纯文本再标，勿直接标乱码）
- 铁律：`object` 必须**逐字**出现在 `text` 里；不编造量化数值；只标真实文档正文

## 我收到后的闭环
核对格式 → 一致性校验 → 转 JSONL 训练集 → 与导师复核 20 条对拍 → GPU 微调 UIE → P/R/F1 评估 → 接入系统 → 跑 `validate_uie_phase8.py` 5 项 → 出报告素材。
