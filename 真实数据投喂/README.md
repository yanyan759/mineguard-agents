# 真实数据投喂

按投喂顺序排列的子目录（对应 `agent1/docs/真实资料爬取与整理要求清单.md` 第七章）：

目录内整理脚本会根据脚本自身位置定位仓库，不依赖开发者电脑的绝对路径。需要合并仓库外的资料时，通过环境变量传入目录或文件：`MINEGUARD_REFERENCE_DATA_DIR`（外部案例资料根目录）、`MINEGUARD_UIE_CSV`（已有标注 CSV）和 `MINEGUARD_UIE_NEW_JSON`（新增标注 JSON）。

| 子目录 | 对应章节 | 投什么 |
|---|---|---|
| `01_事故案例整理/` | 第一章（投喂要求 A） | 按附 A 模板整理的 accident_cases YAML 条目 + 报告原件（18 份已在 `煤矿资料收集/05/`，主要是整理） |
| `02_UIE标注数据/` | 第二章（投喂要求 B + §2.5） | UIE 标注 CSV/JSONL（**模板与 10 条真实示范已备好**） |
| `03_权限矩阵依据/` | 第三章（PM1-PM6） | 774 号条例 / 国发〔2010〕23号 / 安全生产责任制 / 应急预案组织职责 / 叫应通知链 / 四级响应处置动作表 |
| `04_锚定素材/` | 第四章（SA1-SA6） | 采购中标公示 / 设备技术参数 / 支护材料报价 / 班制定员 / 企业年报 / 执法公示，每类 5-15 条 |

**投喂约定**：每份材料登记来源 URL / 采集日期 / 用途；结构化文件优先 YAML/JSON/CSV；PDF/HTML 原件另附供解析。

**每份资料投喂后我的处理闭环**：核对来源与格式 → 整理成 fixture/种子/训练数据精确格式 → 跑对应验证脚本 → 给通过证据 + 报告素材 → 更新进度日志。
